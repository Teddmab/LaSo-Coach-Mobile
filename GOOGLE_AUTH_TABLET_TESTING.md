# Google Authentication - Tablet Testing Checklist

## Implementation Review

### Current Configuration
- **App Owner**: `ohriginal-llc` (from app.json)
- **App Slug**: `laso-coach` (from app.json)
- **Custom Scheme**: `lasocoach` (for deep linking)
- **Redirect URI (Dev Client)**: `lasocoach://auth`

### How It Works
1. **Environment Detection**: The app detects if it's running in:
   - **Expo Go**: Uses proxy URL `https://auth.expo.io/@owner/slug` with Web client ID
   - **Dev Client/Standalone**: Uses custom scheme `lasocoach://auth` with Android client ID

2. **For Development Client (Your Tablet)**:
   - Uses **Android OAuth Client ID** (not Web client ID)
   - Redirect URI: `lasocoach://auth`
   - No proxy needed - direct OAuth flow

## Pre-Testing Checklist

### ✅ 1. Google Cloud Console Configuration

**CRITICAL**: You must configure the Android OAuth client in Google Cloud Console:

1. Go to [Google Cloud Console](https://console.cloud.google.com/apis/credentials)
2. Select your project
3. Find or create the **Android OAuth 2.0 Client ID**
4. In "Authorized redirect URIs", add:
   ```
   lasocoach://auth
   ```
   ⚠️ **Important**: 
   - No trailing slash
   - Exact case: `lasocoach` (lowercase)
   - Must match exactly what the app sends

5. **Package name** should be: `com.laso.coach` (from app.json)
6. **SHA-1 certificate fingerprint**: 
   - For debug builds: Get from `keytool -list -v -keystore android/app/debug.keystore -alias androiddebugkey -storepass android -keypass android`
   - Add this to the Android OAuth client configuration

### ✅ 2. Verify Client IDs

Check that your `.env` file has:
```env
FIREBASE_ANDROID_CLIENT_ID=your-android-client-id-here
FIREBASE_WEB_CLIENT_ID=your-web-client-id-here
FIREBASE_IOS_CLIENT_ID=your-ios-client-id-here
```

## Common Issues & Solutions

### Issue 1: `redirect_uri_mismatch` Error

**Symptom**: Error 400: redirect_uri_mismatch

**Solution**:
1. Check Google Cloud Console → Android OAuth Client
2. Ensure `lasocoach://auth` is in "Authorized redirect URIs"
3. Verify exact spelling (lowercase, no trailing slash)
4. Check logs to see what redirect URI is actually being sent

### Issue 2: App Doesn't Open After Google Sign-In

**Symptom**: Google sign-in completes but app doesn't receive the token

**Solution**:
1. Verify deep linking is configured in `app.json`:
   ```json
   "scheme": ["lasocoach", "com.laso.coach"]
   ```
2. Check Android manifest has intent filters (should be auto-generated by Expo)
3. Test deep link manually: `adb shell am start -W -a android.intent.action.VIEW -d "lasocoach://auth" com.laso.coach`

### Issue 3: Wrong Client ID Being Used

**Symptom**: Logs show Web client ID instead of Android client ID

**Solution**:
1. Check `appOwnership` in logs - should be `'guest'` for dev client
2. If it shows `'expo'`, you're still using Expo Go
3. Ensure you installed the development client APK, not using Expo Go

### Issue 4: "Configuration Google en cours" Error

**Symptom**: Button disabled or shows configuration error

**Solution**:
1. Check that client IDs are loaded: Look for `🧪 Raw firebaseOAuthClientIds at import time`
2. Verify `.env` file has all required client IDs
3. Restart dev server if needed
